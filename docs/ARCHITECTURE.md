# Veilmark · 技术方案与架构

> 轻量级图片版权保护工具：显性水印、智能伪隐性水印、算法盲水印三合一，可多选叠加、可批量处理，全部在浏览器本地完成，部署在 Vercel 上是纯静态站点。
>
> 文中所有数字都来自本仓库的基准脚本（`npm run bench:blind`、`npm run bench:glance`）和单元测试，测试素材是 2400px 的实拍照片加一张合成图。

---

## 0. 结论速览

| 模块 | 推荐方案 | 关键理由 |
| --- | --- | --- |
| 显性水印 | Canvas 2D “印章缓存” + 与画布无关的纯几何排版引擎 | 上百个平铺元素只渲染一次；尺寸按短边百分比计算，批量处理时比例一致 |
| 伪隐性水印 | **四层复合**：相位反转光栅 + 防复印底纹 + 暗部色调 + 等亮度色度，叠加 JND 纹理自适应 | 单一原理只能覆盖一种盗用场景。实测高频层适屏下两区亮度差 ΔY≈1.6 级，最近邻缩放后升到约 12 级（7 倍） |
| 盲水印 | **双引擎**：自研 CDP（经典频域，0 KB）+ Adobe TrustMark（MIT，ONNX，懒加载） | CDP 抗压缩、缩放、截图和调色，但不抗裁剪；TrustMark 补上抗裁剪。两者可叠加且互不干扰（已实测） |
| 载荷 | 56 bit 紧凑指纹 + CRC-16，完整信息存本地注册表（IndexedDB） | 盲水印容量只有约 100 bit，完整信息必须走“指纹 + 登记”模式 |
| 运行时 | Next.js 16 App Router 静态页 + Web Worker 池（Comlink）+ OffscreenCanvas | 图片不出浏览器，不需要服务器，主线程不卡 |
| UI | appica-ui（主设计系统，Base UI）+ shadcn/ui（Luma 风格，Base UI 底座） | 两者都基于 Base UI，token 已桥接 |

## 2. 智能伪隐性水印：方案评估与推荐

### 2.1 三个候选方案

| 方案 | 原理 | 在 Web 上实现 | 日常隐蔽 | 显形是否可靠 | 结论 |
| --- | --- | --- | --- | --- | --- |
| ① 防复印底纹 / 网点频率差 | 背景用细网点，信息区用粗网点，两区平均灰度相同。打印加网（约 150 LPI）解析不了 2px 细网点，只能把它平均掉，而且细网点的周长面积比大，网点扩大（dot gain）更严重、印出来更暗；粗网点能保留下来 | 容易，逐像素计算即可 | 适屏看不出；1:1 放大能看到细纹（纸币、支票底纹也有同样的取舍） | 中。取决于打印尺寸和像素密度是否匹配 | **采用**，作为“打印”触发层 |
| ② CMYK 敏感区 / 色度差 | 挑选屏幕上看着一样、转到 CMYK 后差别很大的颜色 | 能生成，但打印驱动的 ICC/GCR 策略不可控；色域映射通常只会压缩差异，很难放大差异 | 好 | **低**，纯 RGB 文件没有办法控制分色 | **不直接采用**。保留其中“等亮度色度差”的做法，用来针对拉饱和度、平均法去色和分色这几类操作 |
| ③ 高频栅格 / 摩尔纹 | 在奈奎斯特频率附近放置栅格，重采样时混叠 | 容易 | 用“不同角度或频率”编码时，两区频谱不同，1:1 下能看出纹理差异 | 高（只要发生点采样） | **采用并改进为“相位反转”** |

**方案 ③ 的关键改进是相位反转光栅。** 信息区和背景用同一频率、同一角度、同一振幅的栅格，只把信息区的相位翻转 180°。这样两区的均值、能量和频谱幅度完全相同：

- 浏览器或看图软件缩略显示时做的是面积平均，两区都平均成 0，**理论上完全不可见**；
- 最近邻缩放、打印加网、部分平台的缩略算法做的是点采样：背景采到波峰，信息区恰好采到波谷，**两区出现满幅对比**；
- 锐化会放大相位跳变处的边缘。

### 2.2 推荐：四层复合 + JND 自适应

每个像素在 BT.601 亮度上叠加 ΔY，在等亮度色度轴上叠加 ΔC（`lib/watermark/glance/cpu.ts`；WebGL2 版本在 `shader.ts`，公式一一对应）：

```
m ∈ [0,1]   信息掩膜（与显性水印共用排版引擎渲染，经羽化）
s = 2m − 1  信息区 +1，背景 −1
A(x,y)      JND 振幅乘子：局部标准差越大，纹理掩蔽越强，允许的改动越大
h(Y)        高光/暗部余量，避免截断破坏零均值

ΔY = A·h·[ g·carrier(x,y)·(−s)                      相位反转光栅
         + p·((1−m)·checker + m·coarseDot)          防复印底纹
         + t·s·w_shadow(Y) ]                        暗部色调
ΔRGB = ΔY·(1,1,1) + c·A·s·v_iso                     v_iso 满足 0.299r+0.587g+0.114b = 0
最后加入 TPDF 抖动再取整：亚灰阶振幅在 8-bit 量化后仍能保住均值
```

| 触发层 | 针对的盗用场景 | 注意 |
| --- | --- | --- |
| 相位反转光栅 | 重采样、打印、锐化 | 需要无损导出 |
| 防复印底纹 | 打印（网点扩大 + 加网） | 1:1 下能看到细纹，用振幅控制 |
| 暗部色调 | 拉对比度、提亮阴影、去雾 | 属于线性信号，显形倍数有限（见 2.4） |
| 等亮度色度 | 拉饱和度、平均法去色、分色 | 默认用蓝–黄轴（人眼最不敏感）；画面以蓝或黄为主时自动切到红–绿轴，并把振幅降到 0.35 倍（实测红–绿 8 级在 1:1 下就会出现粉斑） |

### 2.3 实测（`npm run bench:glance`，900px 适屏尺度，信息区与背景的亮度均值差 ΔY，单位 8-bit 灰阶）

| 模式 | PSNR | 适屏 ΔY | 最近邻 50% | 打印模拟 | 提亮阴影 | 饱和度 ×3（ΔC） |
| --- | --- | --- | --- | --- | --- | --- |
| 打印显形（峡湾图） | 30.5 | 1.6 | **11.8** | **5.2** | 1.8 | 7.9 |
| 打印显形（树木图） | 30.4 | 1.8 | **12.4** | **7.5** | 1.6 | 5.8 |
| 日常隐藏（峡湾图） | 37.3 | 2.7 | 2.7 | 2.5 | 3.8 | 16.3 |
| 日常隐藏（树木图） | 39.9 | 2.9 | 2.9 | 2.8 | 2.5 | 12.4 |

单元测试 `tests/glance.test.ts` 会断言：高频层在适屏缩略下两区差 < 0.5 级，最近邻重采样后 > 5 级。

### 2.4 能力边界

1. **只有高频层能做到“看不见 → 显形”。** 对比度、曲线这类线性调色，会把图像内容和水印按同样比例放大，所以低频层的“水印/画面”比例基本不变，实测显形倍数只有 1.2–2 倍。高频层之所以能跳 7 倍，是因为“面积平均”和“点采样”之间是非线性关系。
2. **高频层怕有损再压缩。** 社交平台二次 JPEG 会抹掉它；先适屏显示再截屏也会先把它平均掉。截图场景要靠低频层和盲水印。
3. **打印显形依赖输出尺寸。** 2px 级结构要在约 250–300 ppi 输出时才落在打印机加网解析不了的频段。
4. **1:1 放大时能察觉细纹。** 提供了振幅滑杆和放大镜，由用户在隐蔽和显形之间自行取舍。

## 3. 算法盲水印：方案评估与推荐

### 3.1 候选方案

| 方案 | 类型 | 许可 | 浏览器可行性 | 评价 |
| --- | --- | --- | --- | --- |
| Google SynthID | 深度模型 | 闭源 API | ✗ | 不可用 |
| blind_watermark（DWT-DCT-SVD + QIM） | 经典 | MIT | ✓ 易移植 | 对亮度、对比度、Gamma 很脆弱（见 3.2），不能直接用 |
| invisible-watermark（dwtDct / dwtDctSvd / RivaGAN） | 经典 + 模型 | MIT | ✓ | Stable Diffusion 用的就是它的 dwtDct；社区普遍反映它不抗缩放。RivaGAN 面向视频、32 bit。本项目未实测 |
| **本项目 CDP**（Canonical DWT-DCT Pair） | 经典，改进版 | 自研 | ✓ 纯 TS、约 300 行、0 KB 模型 | **推荐：默认引擎** |
| **Adobe TrustMark** | 深度模型（任意分辨率残差） | **MIT（代码和权重）** | ✓ onnxruntime-web，WebGPU 或 WASM | **推荐：增强引擎**。编码器 17 MB，解码器 47 MB（C 变体解码器 22 MB） |
| StegaStamp / Meta WAM / VideoSeal | 深度模型 | 各不相同，WAM 等需核实是否允许商用 | 模型较大 | 作为备选，暂不纳入 |

### 3.2 为什么不直接用 SVD-QIM（实测对照，`npm run bench:blind`）

QIM 量化的是块能量（最大奇异值）的**绝对值**。亮度偏移、对比度、Gamma 都会把整体量化格点平移，比特就会大面积翻转，而截图过程中的色彩管理本身就会带来这类偏移。

| 攻击 | CDP（本项目） | SVD-QIM（同样用规范化尺度） |
| --- | --- | --- |
| JPEG q50 / WebP q75 / 缩放 25% | ✅ | ✅ |
| 对比度 ×1.25 | ✅ | ❌（比特准确率 1–97%，随图而变） |
| Gamma 0.8 | ✅ | ❌（0–57%） |
| 截图（60% + 边框） | ✅ | ❌（未做裁边） |
| 亮度 +10 | ✅ | 部分图片 ❌ |

### 3.3 CDP 设计（`lib/watermark/blind/classic.ts`）

1. **规范化尺度**：Y 通道缩放到长边 1024（小图用 512），这样后续缩放和截图都等价于“换了个输入尺寸”。检测时按同一规则缩放。
2. **Haar DWT 取 LL → 8×8 DCT**，每块用 3 组“同径向频率”的系数对 (1,2)/(2,1)、(0,2)/(2,0)、(1,3)/(3,1)。模糊和压缩对一对系数的衰减基本相同，所以符号关系稳定。
3. **符号调制**：比特 1 要求 a−c ≥ T，比特 0 要求 a−c ≤ −T。亮度偏移只影响 DC，增益只做同比缩放，所以两者**天然不影响结果**；单调的色调曲线也基本保持符号。
4. **JND 自适应**：纹理块的余量 T 放宽到 2 倍，单槽改动设上限；宿主本身强烈反向时放弃该槽位，交给重复编码兜底。
5. **闭环嵌入 3 轮**：规范尺度的残差用双线性放大后叠回原图，再从真实输出重新测量，补偿放大、取整和截断造成的余量损失。
6. **密钥**：用密钥打乱“槽位 → 比特”的映射，并生成白化序列（公开密钥人人可验证，私有密钥只有持有者能检出）。
7. **解码**：截幅软判决，按比特累加 → CRC-16 校验 → 得分 z 需 ≥ 2.5（未加水印的图约 0.8）。另外会自动裁掉截图四周的纯色边框后再试一次。

### 3.4 TrustMark 集成（`lib/watermark/blind/trustmark.ts`）

- 与官方 Python 实现一致：原图缩到 256² → 编码器 → 残差去掉逐通道均值 → 双线性放大回原尺寸再叠加；宽高比 > 2 时只处理中心正方形。
- 100 bit = 72 bit 帧 + 前 28 bit 重复。解码时对重复位做软合并，再对最不可信的 3 位做 Chase 翻转 + CRC 校验，同时要求置信度 ≥ 3（未加水印的图 0.3–0.7，含水印的图约 10）。
- 模型懒加载，默认从 `/models/trustmark` 取（`npm run models:trustmark` 下载），WebGPU 优先，WASM 兜底。

### 3.5 实测

**CDP，默认强度 5**（3 张 2400px 实拍照片 × 17 种攻击 + 合成图）：

| | 结果 |
| --- | --- |
| PSNR | 39.5–44.0 dB（合成图 41.1） |
| 嵌入耗时（2400×1600，Node 单线程） | 150–220 ms |
| JPEG q90/75/50、WebP q75、缩放 25%/50%/150%、截图 60%+边框、缩放 50%+JPEG75、亮度 ±10、对比度 ×1.25、Gamma 0.8、饱和度 ×1.5、高斯噪声 σ5、高斯模糊 σ1.5 | **全部 ✅** |
| 裁剪 5% | ❌（已知局限） |
| 未加水印原图 | 全部未检出（得分 0.71–0.93） |
| 512px 小图 | “缩放 50% + JPEG75”组合失败，其余通过 |

**TrustMark Q**（onnxruntime-node 实测，3 张照片）：PSNR 40.5–44.3 dB；PNG、JPEG q50、缩放 25%、对比度、**裁剪 5% 和 15%** 全部 ✅；未加水印原图全部未检出。

**双引擎叠加**：先 TM 后 CDP、先 CDP 后 TM 两种顺序都测了，合并 PSNR 约 37.2–37.9 dB；PNG、JPEG75、缩放 50% 下两个引擎都能各自解出自己的载荷。

**浏览器端到端**：工作台嵌入的指纹 `3c9337c0f92d9e`，在“显性 + 打印显形 + 最近邻 50% + 缩到 45% + JPEG70”这条攻击链后仍由 CDP 解出（得分 2.92，余量已经很薄）；在“裁剪 15% + JPEG80”后 CDP 失败，TrustMark 以置信度 10.4 解出同一指纹。

### 3.6 载荷、注册表与举证

| 字段 | 位宽 | 说明 |
| --- | --- | --- |
| version | 3 | 版式版本 |
| creator | 24 | 纯数字直接写入（适合工号式 ID），文本经 FNV-1a 折叠 |
| day | 15 | 自 2024-01-01 起的天数，约可用 89 年 |
| serial | 14 | 原图 SHA-256 截断 / 批次序号 / 手动 |
| CRC-16 | 16 | 另加，不计入 56 bit |

指纹不是签名：知道算法的人可以伪造一个指纹。**举证链**是“图里的指纹 → 注册表记录 → 你手上原图的 SHA-256 → 登记时间”。路线图里计划用 Ed25519 给注册表记录签名，并接入 C2PA Content Credentials（TrustMark 本身就是 C2PA soft-binding 的参考实现）。

### 3.7 已知局限

- CDP 不抗裁剪、旋转、透视；TrustMark 抗裁剪，但也不抗大角度旋转。可行的改进：同步模板，或基于特征点的配准（路线图）。
- TrustMark 的载荷任何拿到模型的人都能解出来，**不要放敏感信息**。私有密钥只对 CDP 有效。
- 盲水印的物理容量决定了只能放指纹，放不下任意长度的文本。

## 4. 系统架构

```
┌──────────────────────────── 浏览器（图片不出本机） ────────────────────────────┐
│                                                                                 │
│  Next.js App Router（静态页）                                                   │
│  ├─ /        工作台 Studio      appica-ui + shadcn(Luma)                        │
│  └─ /verify  验证与注册表                                                        │
│        │                                                                        │
│        │ zustand（配置持久化 localStorage；图片与结果只在内存）                    │
│        ▼                                                                        │
│  lib/workers/client.ts ── Comlink ──►  watermark.worker.ts（预览单例 + 批量池）  │
│                                        │                                        │
│                                        ├─ codec      createImageBitmap / OffscreenCanvas / jSquash WebP(WASM)
│                                        ├─ pipeline   显性 → 伪隐性 → 盲水印 → 编码
│                                        ├─ glance     CPU 参考实现 + 盗用模拟
│                                        ├─ blind/CDP  纯 TS
│                                        └─ blind/TM   onnxruntime-web（WebGPU/WASM，懒加载）
│                                                                                 │
│  IndexedDB：本地注册表（idb-keyval）    Cache：ONNX 模型 / WASM                  │
└─────────────────────────────────────────────────────────────────────────────────┘
          ▲ 静态资源（HTML/JS/WASM/ONNX）
   Vercel 静态托管 / CDN（无服务端计算）
```

**管线顺序是刻意安排的**（`lib/watermark/pipeline.ts`）：

1. **显性水印**（Canvas 2D）：先把可见层画上去；
2. **伪隐性水印**：必须排在显性层之后，否则显性层会盖掉它的逐像素高频结构；
3. **盲水印**：最后嵌入，前面任何像素改动都会破坏它的闭环余量；双引擎时先 TM 后 CDP；
4. **编码**：PNG 或无损 WebP；有损格式下高频层失效，UI 会提示。

预览同样走 Worker 做**全分辨率**处理（防抖 280ms）：伪隐性水印是逐像素结构，用缩略图代理预览会失真。`glance/shader.ts` 里的 WebGL2 渲染器已经写好，留给后续“拖动滑杆 60fps 实时预览”使用（见路线图）。

## 7. UI 与交互

- **三栏布局**：素材栏（多选）｜画布（对比、放大镜、盗用模拟、PSNR 与指纹徽标）｜检查器（显性 / 伪隐性 / 盲水印 / 导出四个标签，标签上的圆点表示开关状态）。窄屏时纵向堆叠。
- **任何参数变动 → 280ms 防抖 → Worker 全分辨率重算**，画布即时更新，不需要点“应用”。
- **放大镜**：最近邻 2/4/8 倍，按住 ⌥ 切换原图，用来在 1:1 下检查伪隐性层。
- **盗用模拟**：原图和水印图同时施加同一变换，并排或滑动对比，导出前就能确认水印会显形。
- **批量**：勾选 → 导出页“批量处理并导出已选 N 张” → 进度条 → ZIP；失败项单独列出。
- **验证页**：拖拽/粘贴 → 结果卡片（指纹、创作者 ID、日期、序号、注册表匹配）+ 各引擎的得分明细；注册表可导入/导出。

## 8. 部署（Vercel）

- `next build` 产出的全部路由都是静态页（`○ Static`），没有 Serverless 函数，**零服务器成本**。
- **TrustMark 模型托管**：约 64 MB（Q）。可以选：① 放进 `public/models/trustmark` 随站点部署；② 放到对象存储/CDN（Vercel Blob、R2），通过 `NEXT_PUBLIC_TRUSTMARK_BASE` 指定地址，注意开启 CORS 和长缓存；③ 追求更小体积时用 C 变体解码器（22 MB）。
- **缓存**：`/models/*` 和 `*.wasm` 设置 `Cache-Control: public, max-age=31536000, immutable`。
- **多线程 WASM（可选）**：需要跨源隔离（`COOP: same-origin` + `COEP: credentialless`）。目前不开启，默认 WebGPU 优先，单线程 WASM 兜底。
- **隐私**：不上传任何像素；注册表只存在本机。

## 10. 路线图

**Phase 1（已完成，即本仓库）**：三种水印引擎、四层伪隐性、双引擎盲水印、工作台、批量、验证、注册表、基准与单测。

**Phase 2（体验）**

- 伪隐性参数拖动时切到 WebGL2 实时预览（`glance/shader.ts` 已就绪），松手后再做 CPU 全分辨率计算；
- 多模板管理（命名、导入/导出 JSON）；按图覆盖参数；
- 自定义字体上传（FontFace 同时注入主线程和 Worker）；
- 首次加载 TrustMark 时显示下载进度，模型写入 Cache Storage；
- 批量导出支持 File System Access API 直接写入文件夹。

**Phase 3（安全与生态）**

- 移植 TrustMark 官方 BCH 数据层，与 Adobe/C2PA 生态互通；
- 用 Ed25519 给注册表记录签名，生成可离线验证的“版权证书”；可选接入 C2PA Content Credentials；
- 抗几何攻击：同步模板或特征点配准，覆盖旋转、透视和大比例裁剪；
- 可选的云端注册表（Vercel KV / Postgres），用于团队共享和公开查询。
